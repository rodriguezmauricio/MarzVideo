# Learnings

- [2026-11-15] [claude] Pointer handlers must read the latest drag draft from a ref, not React state: pointerup can arrive before React re-renders after the last pointermove, which committed an empty or stale edit.
- [2026-11-15] [claude] Never define a component inside another component's render (the old timeline resize Handle): it remounts on every render and drops pointer capture mid-drag. Use a render helper function.
- [2026-11-15] [claude] Playwright's own Chromium cannot play H.264 MP4. Browser checks of the editor must use `channel: "msedge"` (or Chrome).
- [2026-11-15] [claude] Vitest does not type-check. Run `pnpm typecheck` as well as `pnpm test`; it caught a narrowing error the tests missed.
- [2026-11-15] [claude] Source frames that are not 16:9 (16:10 laptops, region captures) are letterboxed by `frameAt().dstRect`; zoom rects stay aspect-locked so zooming fills the output.

- [2026-11-16] [claude] This checkout's node_modules were symlinks into a deleted folder (Desktop/MarzVideo), so tsc and vitest were missing. Fix: `CI=true pnpm install --prefer-offline --frozen-lockfile` (no TTY, so pnpm needs CI=true to purge).
- [2026-11-16] [claude] The `.dc.html` mockups render in Edge without support.js: replace `{{accent}}` with the hex and screenshot `.win`. Their computed styles are the reference (e.g. `.win button { padding: 0 }` beats `.lr2` padding).
- [2026-11-16] [claude] design-check flags `el.blur()` and words like "rounded" in comments. Use a `design-check-ignore` comment with a reason rather than renaming the DOM call.
- [2026-11-16] [claude] Fonts are bundled locally (src/assets/fonts, src/styles/fonts.css), the desktop app must work offline. Both are variable fonts, so one woff2 per subset covers all weights: declare weight ranges ("500 700"), not one face per weight.

## Deferred from the M1 editor review (minor, not fixed)

- Mic offset above 40 ms: audio starts at once then jumps back, so the first stretch is heard twice (`Preview.tsx`).
- Inspector blur always commits and rounds to 10 ms; `updateZoom` with identical values still adds an undo step.
- Auto zoom: end not clamped to the duration; a run with no clicks adds an undo step; re-running discards tweaked auto zooms (bare key A makes that easy); a widely spread cluster gives a near full-frame zoom; no overlap check against manual or live zooms.
- Holding Z or C (key repeat) stacks duplicate blocks.
- A missing or unplayable `screen.mp4` leaves a black preview with no message.
- `parseProject` accepts `durationUs: 0` and zero sizes; an unknown `easing` or `origin` value rejects the whole project.
- Dev server middleware has no try/catch; its `project.json` write is not atomic (dev only). The Tauri storage writes `project.json.tmp` and renames, so the atomic write is closed for the app (2026-11-17).
- Header clock shows source length, not export length. The spec line "the timeline maps to output time" now differs from the code (playhead is in source time).
- Sample uses `testsrc` (built-in timestamp) instead of `testsrc2`; there is no `usePlayback.ts` (logic lives in `Preview.tsx`).
- No committed Playwright tests: the browser checks were run by hand.
- Closed 2026-11-17: recorder pin-downs. `durationUs` is the stop time on the QPC clock minus t0, and both tracks are padded or cut to it. Crash recovery takes the length from the screen (`screen.offsetUs` + the last packet + one frame); a shorter mic is kept and padded with silence, a mic without samples is dropped (fixed in the final review: it used to take the shorter track and cut the video to the mic). Mouse `button` is `left`, `right` or `middle` only; other buttons are not written.
- `drawFrame` should scale by the media's real pixel size, not `project.source`, before proxies arrive.

- [2026-11-16] [claude] WGC's default minimum update interval snaps to every 3rd refresh on a 165 Hz screen, so capture gets 55 fps. Request half a frame (8.3 ms for 60 fps) and slot frames by timestamp; that holds 60 fps CFR.
- [2026-11-16] [claude] WGC `SystemRelativeTime` and the WASAPI packet `u64QPCPosition` are both QPC in 100 ns units, so screen, mic and input events share one clock with no conversion beyond units.
- [2026-11-16] [claude] The first WASAPI packet arrives up to 0.7 s after Start, and the mic drops about 20 ms once shortly after (no discontinuity flag). Warm up both tracks before taking t0, and pad mic gaps from the QPC position.
- [2026-11-16] [claude] A low-level mouse hook does not see `SetCursorPos` moves (scripts, remote tools). Poll `GetCursorPos` on a timer as well, or the cursor track freezes.
- [2026-11-16] [claude] `h264_nvenc` accepts BGRA on stdin directly, so the FFmpeg sidecar does no CPU colour conversion (about a quarter of one core at 1080p60).
- [2026-11-17] [claude] WGC stamps frames up to about 10 ms ahead of QPC now (the present time), so frames past the stop time are already queued when stop is read. The CFR writer holds back `ceil(20 ms / slot) + 1` slots (`hold_slots`) before writing, or the video gets one frame too many.
- [2026-11-17] [claude] Capture tests on this laptop record the live desktop: when Mauricio is using it, the content changes and repeat counts are not comparable. Run the 3-minute comparison with nobody at the machine. In PowerShell, pass `[NullString]::Value`, not `$null`, to a `string` P/Invoke parameter (FindWindow), or it becomes "".
- [2026-11-17] [claude] The raw BGRA pipe to FFmpeg holds 60 fps at 1440p (no steady-state stalls over 5 ms) but only barely at 4K (about 2 GB/s, two of four runs under 59 fps, most writes one to two slots late), so capture above 2560 x 1440 pixels is capped at 30 fps. Re-measure with `pipe-bench` on any new encoder or machine before lifting the cap.
- [2026-11-17] [claude] The sync probe's printed render latency is WASAPI stream latency plus queue time only; it leaves out the speaker and mic input paths, so judge sync on spread (17 ms) and mean absolute offset (45 ms) first. `pnpm sync-check` on a synthetic sample (`makeSample` with `syncOffsetMs`) reads the exact offset, which is the check that the analyzer itself is right.
- [2026-11-17] [claude] In the Tauri app media comes from the asset protocol, another origin than the page. A video drawn to a canvas that is read back (`toDataURL`) needs `crossOrigin = "anonymous"`, or the canvas is tainted and the timeline thumbnails stay empty while playback still works.
- [2026-11-17] [claude] The Tauri window can be driven without touching the desktop: start `tauri dev` with `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9333` and attach Playwright with `chromium.connectOverCDP`. Input goes only to the webview.
- [2026-11-17] [claude] A window with `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` is also missing from every screenshot tool, so the recorder overlay and bar can only be looked at on the real screen or through a CDP screenshot of their webview (transparent areas come out white there): plan design checks with the `?fake` pages.
- [2026-11-17] [claude] The two recorder windows share one origin, so localStorage plus the `storage` event syncs them (checked in WebView2: a tiny region drawn on the overlay shows the error on the bar). Mic friendly names on Windows can be 70+ characters: always cap name widths in bars.
- [2026-11-17] [claude] `ResizeObserver` watches the content box by default, so a padding change (the recording bar's tooltip room) fires nothing; observe `{ box: "border-box" }` when the window must follow padding too.
- [2026-11-17] [claude] Two threads of one process cannot `RegisterHotKey` the same keys: the recorder's setup hotkeys run on their own input thread and must be stopped (joined) before `Session::start` registers them again, and armed again when a start fails.

- [2026-11-17] [claude] A WebCodecs `VideoDecoder` has a small output frame pool (about 8 in Edge): holding about 7 undrawn VideoFrames while awaiting `flush()` deadlocks it. Export's FrameSource never awaits flush while holding frames and settles each output as it arrives.
- [2026-11-17] [claude] In Chromium `video.currentTime` is the raw MP4 presentation time (screen.mp4 starts at the B-frame delay, 50 to 67 ms, no edit list), so export decodes by raw cts. But a paused seek to a time just before a keyframe (within that delay) shows the keyframe instead: pick preview-vs-export compare times away from keyframes (Task 16 PSNR step).
- [2026-11-17] [claude] With B-frames screen.mp4 (fragmented, no edit list) starts at the reorder delay (50 ms with nvenc at 60 fps), but frame 0 is the frame captured at `screen.offsetUs`; mapping source time to raw pts showed the picture 50 ms late in preview and export, and `pnpm sync-check` on the folder (frame index based) cannot see it. Fixed: the recorder encodes with `-bf 0`, and preview and export map with `mediaTimeUs(project, srcUs, firstFrameUs)` (first cts from mp4box; the preview reads it with a 1 MB Range request) so older recordings line up too.
- [2026-11-17] [claude] Export frames are taken with floor semantics (the source frame current at that time, like the playing video), so a flash lands up to one output frame late in the export (25 ms with a 41.7 ms screen offset at 30 fps). A sync check against the raw project must allow one output frame, or align the screen offset to the output frame grid.
- [2026-11-17] [claude] WGC sends no frame at all on a static screen, so a recording of an unchanging desktop would have no video. Keep the last warm-up frame as slot 0 and repeat it; the stop path must not wait for a new frame.
- [2026-11-17] [claude] `h264_nvenc` with B-frames puts the first frame at 0.033 to 0.05 s and shifts picture against audio. Record with `-bf 0` (frame 0 at 0, `screen.offsetUs` is the real first-frame time).
- [2026-11-17] [claude] `apad=whole_dur` on an empty `atrim` hangs FFmpeg. For a segment past the end of the mic, generate silence (`anullsrc`) instead of padding an empty input.
- [2026-11-17] [claude] Chromium `video.seekable.start(0)` is 0 even when the first frame is later, so it cannot tell the first frame time. Read the first cts from the MP4 (mp4box) instead.
- [2026-11-17] [claude] Windows 125% scaling on a 1080p laptop gives a webview of about 1536 x 780, so a 1440 x 900 layout overflows. Check every screen at 1280 x 720 and at the real window size, not only 1440 x 900.
- [2026-11-17] [claude] Export loads the whole `screen.mp4` into the webview before decoding (about 17 MB per minute of 1080p60 screen video, 40 MB/min on a busy screen), so a very long take costs that much memory during an export. Stream the file (range reads) before takes of an hour or more are common.
- [2026-11-17] [claude] A raw NUL byte in a Rust byte string (`b"RIFF\0..."` typed as real NULs) makes git treat the whole file as binary: no diffs, no line-ending normalization. Write `\0` escapes; `.gitattributes` now forces LF for text and marks images and fonts binary.
- [2026-11-17] [claude] A page cannot wait for an async save in `beforeunload`, so the window close button lost the last 2 s of edits. Tauri holds the close (`CloseRequested`, `prevent_close`), asks the page to save (`app://flush`), and the page calls `close_main`; a 3 s fallback closes it anyway.

- [2026-11-18] [claude] WebView2 multiplies its pixel ratio by the Windows text size (Accessibility > Text size), not only the display scale. On this laptop the display is 100% (window DPI 96, Tauri `scale_factor` 1.0) but the recorder pages ran at `devicePixelRatio` 1.25, so the overlay drew the region 25% too large and the bar window was cut on both sides. The recorder pages now convert with their own `devicePixelRatio` and send physical pixels to Rust (`fit_bar`, `overlay_hits`); never use the monitor's scale for webview CSS pixels.
- [2026-11-18] [claude] A transparent full-screen overlay on Windows cannot be click-through per pixel. The recorder overlay toggles `set_ignore_cursor_events` from a 16 ms thread that reads `GetCursorPos` against the hit rects the page reports, and never toggles while a mouse button is down (drags keep going). Check it with `WindowFromPoint` and `WS_EX_TRANSPARENT` (scratch script pattern: move the cursor, read the style), not with CDP input, which bypasses Windows hit testing.
- [2026-11-18] [claude] A second Tauri dev copy cannot start while the installed app runs: both use the same WebView2 profile with different browser arguments (`0x8007139F`). Set `WEBVIEW2_USER_DATA_FOLDER` to a scratch folder for the dev copy.
